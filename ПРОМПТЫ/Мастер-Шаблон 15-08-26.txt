
   Создай полностью готовую статическую веб-страницу `index.html` для интерактивной карты русскоязычных специалистов, услуг и организаций в городе Сидней, Австралия.

Проект:
Russian Friendly

Главная задача:
создать полезный локальный каталог для русскоязычных жителей, эмигрантов, туристов и новых жителей Сиднея, который одновременно:

* удобен реальному пользователю;
* хорошо индексируется Google;
* корректно обнаруживается и индексируется Bing;
* может использоваться Bing Copilot и другими AI/GEO-системами как источник информации;
* содержит понятные, проверяемые и самостоятельно читаемые факты;
* не выглядит как автоматически созданная SEO-страница;
* не использует keyword stuffing;
* не содержит вымышленных организаций или фактов.

Страница должна быть самостоятельной: пользователь должен получить основную полезную информацию непосредственно из URL без необходимости обращаться к внешнему контексту.

2. ГЛАВНЫЕ ПРИНЦИПЫ GOOGLE + BING + AI/GEO
==========================================

Страница создаётся прежде всего для пользователя.

SEO и GEO должны быть естественным следствием полезного содержания, а не заменять его.

Обязательно соблюдать следующие принципы:

1. Полезность для пользователя важнее количества ключевых слов.

2. Контент должен полностью соответствовать поисковому намерению пользователя.

3. Каждая страница города должна иметь уникальное содержание, относящееся именно к этому городу.

4. Нельзя создавать страницу простым копированием текста другой городской страницы с заменой названия города.

5. Не использовать одинаковые SEO-тексты, FAQ, описания категорий и вводные блоки на всех городах с механической заменой города.

6. Не использовать искусственно повторяющиеся поисковые фразы.

7. Не создавать текст только ради поисковой оптимизации.

8. Все важные факты должны быть понятны непосредственно из страницы.

9. Не выдумывать организации, адреса, телефоны, сайты, координаты, цены, отзывы, рейтинги или другие факты.

10. Если достоверной информации недостаточно, лучше показать меньше организаций, чем добавлять непроверенные данные.

11. Не называть организацию «проверенной», если Russian Friendly действительно не проводил проверку.

12. Не использовать cloaking.

13. Не показывать поисковым системам содержание, существенно отличающееся от содержания для пользователя.

14. Не использовать скрытый SEO-текст.

15. Не использовать `display:none`, `visibility:hidden`, `opacity:0`, off-screen positioning или аналогичные методы для сокрытия поисковых фраз.

16. Не создавать страницы, состоящие преимущественно из списков ключевых слов.

17. Не копировать и не переписывать чужой контент без добавления самостоятельной ценности.

18. Не создавать искусственные внешние ссылки или ссылочные схемы.

19. Структурированные данные должны точно соответствовать видимому содержанию страницы.

20. Не добавлять в JSON-LD сведения, которых нет на странице или которые невозможно подтвердить.

21. Основная информация должна находиться ближе к началу страницы.

22. URL должен иметь одну основную тему:
    русскоязычные специалисты, услуги и организации в Сиднее.

4. РЕАЛЬНЫЕ ОРГАНИЗАЦИИ И ИСТОЧНИКИ
===================================

Все организации должны основываться только на открытых источниках.

Для каждой организации по возможности указывать:

* название;
* категорию;
* адрес;
* телефон;
* официальный сайт;
* координаты;
* краткое описание;
* источник информации.

Не выдумывать:

* организации;
* специалистов;
* адреса;
* телефоны;
* сайты;
* координаты;
* рейтинги;
* отзывы;
* цены.

Если информация найдена в открытом источнике, но не подтверждена самой организацией, не называть её «проверенной».

Использовать формулировки:

«Организация представлена в каталоге.»

или:

«Контакты найдены в открытых источниках.»

или:

«Информация представлена по данным открытого источника.»

Если Russian Friendly действительно проверил контакт, можно использовать:

«Проверено Russian Friendly.»

Не использовать эту формулировку без фактической проверки.

Для каждой организации по возможности добавить ссылку на официальный сайт.

============================================================
5. HTML-КАТАЛОГ ДОЛЖЕН БЫТЬ ДОСТУПЕН БЕЗ JAVASCRIPT
===================================================

Критически важная информация не должна существовать только в JavaScript.

Основные сведения об организациях должны присутствовать непосредственно в HTML-каталоге.

Для каждой организации создать HTML-карточку:

* название;
* категория;
* адрес;
* телефон, если подтверждён;
* официальный сайт, если найден;
* описание;
* источник/статус информации.

JavaScript-массив `DATA` использовать для:

* карты;
* маркеров;
* фильтрации;
* связи карты с каталогом.

Но HTML-каталог является основным доступным контентом страницы.

Не полагаться исключительно на client-side rendering для критической информации.

19. SEMANTIC TOPICS
===================

Создать отдельный видимый блок:

<h2>Что ищут русскоязычные жители Сиднея</h2>

Задача блока:

показать пользователю основные направления поиска, а не создать скрытый или искусственный SEO-текст.

Использовать 55 исходных поисковых тем как семантическую основу.

ВАЖНО:

Все 55 тем должны присутствовать на странице, но не обязательно в исходной форме.

Не превращать блок в механический список:

«русский врач Сидней»
«русскоязычный врач Сидней»
«врач на русском Сидней»

Вместо этого преобразовать поисковые запросы в естественные пользовательские темы.

Например:

«Русскоязычные врачи в Сиднее»

«Стоматологи, говорящие по-русски»

«Юристы и адвокаты с консультациями на русском»

«Переводчики с русского языка»

«Русскоязычные риелторы и помощь с арендой»

и т.д.

Каждый элемент:

<div class="query">...</div>

============================================

Страница должна быть:

* discoverable;
* crawlable;
* indexable;
* understandable;
* accurate;
* original;
* locally relevant;
* independently verifiable;
* useful to humans.
